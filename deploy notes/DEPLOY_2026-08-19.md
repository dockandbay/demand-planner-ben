## 2. Database migration — **235 (required)**

**`migrations/235_v_po_finance_blank_deposit_est.sql`** rebuilds `planner.v_po_finance`.

- It is a **DROP VIEW + CREATE VIEW**, *not* CREATE OR REPLACE. Reason: the view's base does `SELECT po.*`, and table columns added since the view was last built (e.g. mig 138 `dtc_approved_snapshot`, plus an `is_master` column) shift the `po.*` column order, which CREATE OR REPLACE rejects. **Nothing in the DB depends on the view** (both the admin query and the portal read it at runtime), so the drop is safe. The migration was authored from the **live view definition** (`pg_get_viewdef`), not the stale mig-123 text, so it already matches the current schema.
- **Run it before/with the server deploy** (the deposits + cash-flow reads use the new estimate). Applied + verified in Ben's sandbox.
- **Behaviour change (only for blank deposits):** a deposit whose amount is **blank/0** (a real deposit row, not the `NO DEPOSIT` sentinel) is now treated as pre-funded to its **estimated total** = Σ of its open linked POs' start deposit. Real-amount deposits are **byte-identical** (the availability cap still applies); `NO DEPOSIT` / dangling refs are untouched.

## 3. ⚠ Cash Flow hotfix (live is currently 500-ing)

`server.mjs` `cashflowResponse()` had a stray alias typo introduced by v27.6.2 (675f1ec): `f.shipment_name=r.shipment_ref` in a query with no `r` alias → Postgres `42P01 missing FROM-clause entry for table "r"` at parse time. **Cash Flow has been 500-ing on every request since 14 Aug.** Fixed to `sh.shipment_ref` (v27.156). Pulling this batch restores live Cash Flow — please smoke-test SUPPLY ▸ Payments ▸ Cash Flow after deploy.

## 4. What changed (v27.136 → v27.167)

**Blank-deposit ESTIMATE (v27.156–158, mig 235).** A not-yet-funded deposit behaves as if its amount = its estimated total (Σ linked-PO start deposit). Shows in the Deposits report (Amount `~N est`, Remaining `est N`), in Cash Flow (estimated pool line), and in the PO drawdown (linked POs draw their full start deposit instead of it rolling into completion). **Payments Due unchanged** — still reads the entered amount, so an estimated deposit stays hidden there until a real amount > 0 + due date is entered.

**Deposits register overhaul (v27.144–162).**
- "Linked purchase orders" column is now a **PO Ref · Allocated · Estimated** mini-table with a Σ total (allocated takes priority over estimated; per-PO estimate reads `v_po_finance.start_calc`).
- **Dates** column merged (Due / Likely / Paid, Likely hides once paid); **Amount** shows thousands separators; **Xero code** column dropped (derived from the production).
- **Supplier** is now a searchable picker (no free-text); **PROD#/Supplier** picks apply **optimistically** (instant, stay in edit, silent background refresh).
- **Delete** a deposit with linked POs → prompt **NO DEPOSIT / UNASSIGNED / Cancel** (re-points the POs, then deletes; idempotent).
- **Cache fix:** delete + apply-all now bust the server section cache (deposits/PO/cash-flow) so a reload reflects reality (stale-linked-POs bug).

**REPORTS ▸ Performance (new, v27.167).** New **Performance** tab in the top-level REPORTS hub (deep-linked `#/reports/performance/<sub>`):
- **Supply metrics** — the Metrics report **moved here** from SUPPLY ▸ BI & REPORTS (removed there; legacy `#/supply/reports/metrics` redirects). `window.renderSupplyMetrics` exposed from inject; `renderBIMetrics` now takes a host arg.
- **Inventory metrics** (new) — 3PL discrepancy (UK/US/AU/EU, SKUs > 10% vs ERP), FBA discrepancy (> 10% per market), FBA aged (storage cost + units > 270 days) per market. Reconciles the latest uploaded 3PL/FBA reports on open (~9 status fetches).

**Mobile card layouts.** Flexport (v27.137); the four Payments tables — Deposits / Other Payments / Payments Due / Payments Report (v27.148); Stock Availability (v27.163); Inventory Status Report (v27.166); Manage 3PL all-country tabs (v27.165). Desktop tables unchanged throughout.

**Manage FBA.** Reserved Staging folded into on-hand + the 3 columns shown (v27.142); **US AWD** now accepts EITHER the daily ledger OR the new per-SKU "AWD inventory report" (v27.162, auto-detected; reconciled).
