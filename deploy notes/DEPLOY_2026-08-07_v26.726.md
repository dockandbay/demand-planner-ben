## Themes (v26.721 → v26.726)

**Performance — DEMAND page & first paint**
- **v26.721** DEMAND plan: notes (N) and record-of-change (R) rails now load
  lazily / non-blocking *after* first paint, so the grid renders without waiting
  on them.
- **v26.722** Server: the injected page-data build (`_dataCache`) is now
  **boot-warmed** and served **stale-while-revalidate** (5-min TTL, single-flight
  refresh). Kills the ~26s cold-build spike a first request used to eat after a
  cold start. `server.mjs` only; no schema/data change. A forecast save still
  nulls the cache (unchanged).

**Performance — SUPPLY ▸ Actions (v26.726)**
- The full Actions build (big SQL union + expedite/submission/manufacturing/ERP
  layers) is now **cached server-side for 10 min**, boot-warmed, and refreshed in
  the background when stale (stale-while-revalidate). Warm response ~0.7s vs a
  multi-second cold build.
- The **priority preview** (`?scope=priority`) is now *derived from the same
  cached set* filtered to high severity — so it can't drift from the full list.
- The per-action **snooze/dismiss/done overlay is still applied fresh on every
  request** (reads `planner.supply_action_state` each time), so lifecycle changes
  reflect immediately.
- Freshness after edits: the client drops the server cache
  (`POST /api/supply/actions/invalidate`, debounced) and re-warms it whenever
  `invalidateDerived` fires, so a just-fixed action clears right away rather than
  lingering ≤10 min. Client also keeps `cache['actions']` warm every 10 min so
  opening ACTIONS renders instantly from cache.
- ⚠️ Consequence to be aware of: a change made **outside the app** (e.g. an
  n8n/ERP sync updating a PO) won't surface a new/resolved action until the cache
  refreshes (≤10 min). In-app edits reflect immediately via the invalidate hook.
  Drop `ACTIONS_TTL_MS` in `server.mjs` if faster external reflection is wanted.

**DEMAND ▸ Summary with targets**
- **v26.723** Inherited quarter/month cells now show `↳+N%` on a green background,
  matching the format of an explicitly-entered growth figure.
- **v26.724** Added a **"Review target recommendations"** button that opens the
  recs drawer; each month rec now shows **two baselines to target** — `ly <last-year
  units> → <target>` (the growth basis) and `fc <current forecast> → <target>`,
  each with its own growth %.
- **v26.725** Applying a target recommendation **no longer hides the row**: it shows
  **✓ applied** (green row + "(applied)" tag) with an **↩ undo** button. Undo restores
  the pre-apply forecast-override snapshot and drops the row from the open / "Apply
  all open" count. State is in-memory in the artifact (no persistence needed — the
  applied overrides ride the normal Save Forecasts path).
