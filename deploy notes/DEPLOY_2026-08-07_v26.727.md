**DEMAND cell indicators + notes + do-not-smooth (v26.690–704, 721; app_settings smooth_locks)** — vertical indicator rail (i = BI rule, C = calendar, N = note, S̶ = do-not-smooth) at category + SKU level; do-not-smooth engine (SKU-only; locked cells held fixed, others fill the subcat target); double-click notes at SKU + category (dd-mmm-yy dates); global 120ms tooltips app-wide; large growth % abbreviated to ±Nk%; override input = right 50% of the cell; FY-boundary border fix. **Includes a critical fix** (v26.704): `dateDMY` was out of scope in the note code and blanked the whole plan — resolved. **v26.721** the N (notes) and R (record-of-change) rails now load lazily/non-blocking *after* first paint.

**Record of change "R" (v26.711–712, 718; mig 199)** — per-cell audit log (who/what/when) for manual edits, smoothing, target-recommendation apply, and do-not-smooth lock; rail "R" (only when the More-Filters "Show record of change" toggle is on) → click for descending history; "Hide for past months" toggle (default on); manual edits batched into the 60s autosave.

**Performance — server caches (v26.722, 726, 727)** — **v26.722** the injected page-data build (`_dataCache`) is now boot-warmed and served stale-while-revalidate (5-min TTL, single-flight), killing the ~26s cold-build spike a first request used to eat after a cold start (a forecast save still nulls the cache). **v26.726** SUPPLY ▸ Actions: the full action set (big SQL union + expedite/submission/manufacturing/ERP layers) is cached server-side for 10 min, boot-warmed + background-refreshed; priority preview is derived from the same set; the snooze/dismiss/done overlay is still applied fresh per request; the client drops+re-warms the cache after edits (via the invalidate endpoint) and every 10 min. Warm ~0.7s vs multi-second cold. **v26.727** shared read-cache framework (boot-warm + single-flight + stale-while-revalidate, 10-min TTL) applied to the heaviest user-independent SUPPLY reads: **PO rows** (one `PO_ROWS_SQL` build feeds the PO grid + Cash Flow — grid ~2–4s→~0.5s, cashflow 4.2s→2.2s; archive filter moved to JS over the cached set, byte-identical & verified; per-supplier/portal path stays live), **lookups** (0.9s→~0.003s), **order-plan-exceptions** (0.58s/4.5s-cold→~0.002s). All caches drop together on any edit via the client hook — now `POST /api/supply/cache/invalidate` (the old `/actions/invalidate` still works as an alias). ⚠️ Note: changes made **outside the app** (n8n/ERP sync) surface only after the ≤10-min refresh; in-app edits reflect immediately. **⚠️ Vercel caveat: these in-process caches help within a warm lambda but do NOT persist across cold starts or share across instances — boot-warm + SWR still helps under sustained load; consider Redis/Vercel KV later for cross-instance caching.**
