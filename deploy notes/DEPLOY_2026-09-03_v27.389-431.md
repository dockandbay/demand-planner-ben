## Migrations (apply in order)

**255_product_stage_bulk_colour.sql — APPLY (required).** Adds `planner.product_dev_items.bulk_colour_name` (text) and `stage` (text, NOT NULL DEFAULT `'sample_development'`), an index on `stage`, and backfills `stage` from `status` (`approved`→`approved`, `dropped`→`stop_development`, else `sample_development`). This is the PRODUCT **stage state-machine** + bulk-colour name that the whole PRODUCT redesign and samples flow read/write. Approval (`status`, read by PIM / Buy Plan / POs) still **derives** from the terminal stage — no behaviour change to `status`. Sandbox-applied + verified.

**256_product_sample_aspect_feedback.sql — APPLY (required).** New table `planner.product_sample_aspect_feedback (id, sample_id → product_dev_samples ON DELETE CASCADE, aspect, feedback, decision, updated_by, updated_at, UNIQUE(sample_id,aspect))`. Holds per-aspect (Product / Packaging / Labels / Polybag / Other) sample feedback + approve/reject. No live data yet. Powers the redesigned Samples card.

**257_sample_received.sql — APPLY (required).** Adds `planner.sample_requests.received_at` (timestamptz). Marks a shipped sample request as received; the app then forward-advances every linked product to stage **Sample in review**. Additive.

**258_product_timeline_tags_snippets.sql — APPLY (required).** New tables `planner.product_timeline_tags` (name, colour, sort, active) and `planner.product_timeline_snippets` (body, sort, active), plus `planner.supplier_notes.tags jsonb NOT NULL DEFAULT '[]'`. Backs the PRODUCT-timeline tags/badges + "/" quick-phrase picker + tag filter. The `tags` column is only read/written by the product timeline; safe on the shared notes table. No live data yet.
