## 2. What changed (v27.168 → v27.169)

**Every `catch → res.status(500)` now logs its route + stack.**
- v27.168: the `/api/supply/:section` catch (the one that hid the 5-day dead Cash Flow) now `console.error`s the route + stack before returning 500.
- v27.169: extended server-wide to **all ~407** 500-catch sites (all response shapes — `.json` / `.end` / `.send` / `{ok:false}`, plus the ROLLBACK / setLog / logRun variants).

**How:** a `log500(e)` helper backed by an `AsyncLocalStorage` request context — one middleware (`app.use((req,res,next)=>_reqStore.run({req},next))`) wraps every request, so `log500` can name the route **even inside helpers with no `req` in scope** (e.g. `patch()`). Each 500 logs:
```
[500] <METHOD> <originalUrl> — <error stack>
```

**Verified locally:** a forced bad-numeric POST logged `[500] POST /api/supply/deposit/999999 — invalid input syntax for type numeric: "…"`. Normal requests unaffected (middleware is transparent; boot + 200s confirmed).

## 3. Notes

- No DB change, no secrets, no new env/deps. Pure logging.
- After deploy, a future dead endpoint will name itself (method + path + stack) on the **first** request in Vercel's logs, instead of only surfacing as `/api/index`.
- `AsyncLocalStorage` is standard Node (`node:async_hooks`) — works on Vercel's Node runtime.
