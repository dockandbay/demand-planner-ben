## Server changes (server.mjs)

1. **Theme + fonts served by the app.** `GET /hz-theme.css` (served with `?v=<APP_VERSION>` for cache-busting) and `GET /fonts/:name` (reads `supply/assets/`, whitelisted names only). Both are **added to the auth-gate bypass list** next to `/api/version`, because the supplier portal needs them before login. `HZ_THEME_LINK()` injects the `<link>` into the `<head>` of both the app page and the portal page at serve time. If the Vercel build strips non-JS assets, make sure `supply/assets/*.woff2` and `supply/hz-theme.css` ship with the function bundle (they are read with `readFileSync(new URL(..., import.meta.url))`, same pattern as `portal.html`).
2. **Demand plan: closed-SKU rows (v27.473).** `buildSKURAW` runs one extra query: products with `in_planning_scope = false` that have any `planner.sales_actuals` row in the last 36 months. They are added as read-only "last-year-only" rows (`lyo:true`, no availability, no buy). Cost is one `EXISTS` per out-of-scope product against `sales_actuals(sku, month)`; on sandbox it is sub-second. Given the 12-Aug cold-start incident, please confirm `sales_actuals` has an index covering `(sku, month)` on live before the first deploy, or watch the first cold start.
3. **Portal: `GET /api/portal/me` now async and returns `zh_enabled`** = supplier's `planner.suppliers.country` matches China. Portal shows the EN / 中文 toggle and bilingual menus only when true.
4. **Portal price list cache.** `plPortalDataCached()` caches the price-list payload for 2 minutes per supplier; the existing POST middleware clears it on any write to `/api/portal/*` or `/api/supply/price-list*`. Read-only speed-up, no data change.
