## What changed

**v27.660 — Customise barcodes: optional part number per SKU (SERVER + client).**
- Each SKU in a Customise-barcode project can carry an optional **part number** (e.g. `33-55667`), printed on its own line **directly above the barcode** on product / carton / inner labels.
- Stored in the existing `barcode_projects.overrides` **jsonb** as `{num, types, pn}` — **no migration** (same mechanism the per-SKU `types` already use); existing projects untouched. Round-trip verified (save → reload keeps the part number).
- server.mjs: the `barcode-project` save captures `pn`; the label-data custom-project path puts `pn` on the row so the portal "Download custom barcodes" gets it too. Client: a "Part no." column in the Customise editor + `pn` drawn in `buildLabelSVG`/`buildCartonSVG`.

**v27.661 — Supplier portal: native `confirm()` → in-page confirm sheet (client only).**
- The portal's browser `confirm()` popups become a styled in-page sheet (`_ppConfirm`, promise-based; backdrop/Escape/Cancel dismiss, red primary for destructive actions). **15 of 16** sites converted (delete file/attachment/document, remove SKU/document, submit document, confirm/withdraw order, escalate shipment, email note) — their handlers are now `async`/`await`.
- The one left native is `confirmNoBatch` (a "no batch selected — download anyway?" guard inside the synchronous barcode-download pipeline; converting it means making that whole pipeline async — deferred, rare edge).

**v27.659 — White line above the HORIZON bar (your report) — actual fix.**

Fix: dropped the bar's dead `-8px` and pull the wrapper up instead — tagged it `.hz-topwrap`, added `@media (min-width:641px){#app .hz-topwrap{margin-top:-8px}}`. Bar now flush; desktop-only (phone uses the fixed `#hz-topbar`).
