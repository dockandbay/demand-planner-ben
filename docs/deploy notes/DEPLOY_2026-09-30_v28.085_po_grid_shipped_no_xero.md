# v28.085 — PO grid exception: "Shipped · no Xero invoice" (30-Sep-2026)

Small feature (Ben). Server + client, **no migration** (uses `planner.po_links` from mig 311), no env var.

## What

New option in the PO grid ⚠ exceptions dropdown: **"Shipped · no Xero invoice"** — POs whose status is
SHIPPING / DELIVERED / COMPLETE (P50+ only, i.e. Xero-era) that have **no linked Xero bill**. It sits next to the
existing "Shipped · no final invoice" (which keys off the supplier-submitted invoice VALUE on the PO); this one
keys off whether a Xero ACCPAY bill is actually linked in the books.

## How

- `server.mjs` `PO_ROWS_SQL`: new boolean column `xero_linked` —
  `EXISTS (… planner.po_links WHERE system='xero' AND status='linked' AND external_id<>'')`. Same source as
  Linked Records + the Xero payments Exceptions view; resolved by the `resolve-po-links` cron / the Linked-Records
  "find". No new query on the grid path (it rides the cached `poRowsCache` build).
- `supply/inject.html`: `shippedNoXeroInvoice(r)` (mirrors `shippedNoInvoice`, guard `prod_no >= 50`), wired into
  `excMatch` under key `shipped_no_xero`, and a new `<option>` in the exceptions `<select>` with a live count.

## Verified (sandbox)

978 POs linked to a Xero bill; the filter surfaces 23 shipped P50+ POs with none. Dropdown selects, grid narrows
to SHIPPING/DELIVERED/COMPLETE rows, no console errors.

## Prod notes (Diviyaj)

Pull only. The count is only meaningful once `resolve-po-links` has run on prod (it populates `po_links`); until
then every shipped P50+ PO reads as unlinked. No schema change.
