# ⚠ Hotfix on top of the package — v28.080 · migration 316

**Apply `316_v_po_finance_flexport_split_fix.sql` to prod** (CREATE OR REPLACE VIEW, no
data change). It supersedes migration 314's freight split.

## Why
314's pallet-split used `COALESCE(po_pallets/shipment_pallets, 1)` — so a PO with **no
pallet estimate** got the multiplier `1` = **100% of the shipment freight**. On shipments
where any PO had null pallets this over-counted: an all-null shipment gave every PO the
full freight (e.g. PO-49UKXR7: 6 POs × £3,622.58). This is the residual reason your prod
`Σ flex_quote = 745,654` is still too high.

## Fix (316)
`flex_quote = freight × ( CASE WHEN shipment_pallets > 0 THEN coalesce(po_pallets,0)/shipment_pallets
ELSE 1.0/shipment_po_count END )` — pallet share when the shipment has pallet data (a
null-pallet PO takes 0), else an **equal 1/N split**. Adds `ship_n` to the palshare lateral.

## Verified in sandbox (reconciles to the single shipment freight)
- PO-56USXR1 (7 POs, all with pallets): Σ = £10,952.84 = freight ✓ (unchanged)
- PO-49UKXR7 (6 POs, all null pallets): 6 × £603.76 = £3,622.56 ≈ freight ✓ (was 6× full)
- PO-55UKXR2 (5 POs, one null): null PO → £0, rest split to £5,151.06 = freight ✓
- Sandbox Σ flex_quote 638,717 → **497,556** after the fix.

Expect the prod total to drop from 745,654 to the corrected figure once 316 is applied.
Same sanity check: on a shared shipment, Σ(per-PO flex_quote) should equal that shipment's
