# v28.087 — DEMAND cold-render prewarm (30-Sep-2026)

Perf (Ben: "demand plan really slow to load on sidebar click, first click is the worst / cold load").
`supply/inject.html` only, **no migration, no env var, no server change, no artefact logic change**.

## Diagnosis

Clicking DEMAND cold took **~15.7 s** (measured on sandbox). Breakdown from wrapping the artefact's `render()`:
- First `render()` = **12.9 s**, triggered by the DEMAND view-toggle button.
- A second `render()` = 2.7 s fires afterwards from an artefact post-load callback.

The 12.9 s is almost entirely `buildLiveDemand()` — the artefact's `render()` runs it once, the first time DEMAND is
opened, when `DEMAND_BUILT` is false (it computes set shares + explosion across all ~2,000 SKUs). Since SKU data is
now lazy-loaded (v28.081), the lazy loader builds `augmentSKUM` + `buildLiveBpOverlay` but **not** `buildLiveDemand`,
so that ~10 s one-time cost lands on the user's first click. No main-thread long tasks were flagged — it's one long
synchronous compute.

## Fix

`buildLiveDemand()` is a **pure in-memory compute** (no DOM — `renderMain` paints separately), so it's warmed in the
background once the real SKU data is in: a poll waits for `SKU_DATA_READY`, then `requestIdleCallback` runs
`buildLiveDemand()` at a quiet moment (never mid-interaction). JS is single-threaded, so a click that beats the warm
just builds it itself (render's own `!DEMAND_BUILT` guard) and the warm then no-ops — never a double build. Guarded to
run at most once, gives up after 60 s, and no-ops when `DEMAND_BUILT` is already set (non-lazy loads, or the user
opening DEMAND first).

## Measured (sandbox)

| | before | after |
|---|---|---|
| First DEMAND click, cold | ~15.7 s | **~4.0 s** (first render 3.3 s) |
| `DEMAND_BUILT` at click time | false → rebuilds | already true (warmed in background) |

The ~10 s build still happens once, but in the background right after landing (when the user is reading the SUPPLY
grid), not on the click. Grid renders identically (verified: full data, 75 category rows, no console errors).

## Prod notes (Diviyaj)

Pull only. Client-side; applies on both live and sandbox. If `?lazysku=0` (opt-out of lazy SKU), the demand overlay
already builds at load and `DEMAND_BUILT` is set early, so the prewarm correctly no-ops.
