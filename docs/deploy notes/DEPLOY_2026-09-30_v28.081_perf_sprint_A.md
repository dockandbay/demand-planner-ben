# v28.081 — Performance Sprint A (30-Sep-2026)

Follows the full performance audit (report: https://claude.ai/artifact/1MHmSCT4PX67PcUkVrnLy2). Server + client
only, **no migration, no env var, no product-logic change**. Every payload stays byte-identical; what changes is
when it is computed and how often it is fetched.

## server.mjs

- **Shell (`GET /`)**: the user-independent "fresh" wave (8 builders + 7 allSettled builders + `app_settings` +
  products retail scan) is one parallel wave behind `shellFresh()` (60 s stale-while-revalidate memo). Dropped by any
  successful non-GET `/api/*` request (middleware just above the route), by `invalidateDataCache` and by
  `invalidateSupplyCaches`, so the load right after an edit still rebuilds. The ~12 per-key `app_settings` reads are
  one `key = ANY($1)` read (`_AS[key]`, same row shape). `permsFor` runs alongside. Stage timings logged in DEV or with
  `HZ_PROFILE=1` (`[perf /] {...}`).
- **`lazysku` is now the default** (`?lazysku=0` opts out). Client path unchanged (`/api/demand/sku-data`).
- **Section response cache** (`cashflow`, `bi`, `manufacturing`, `payments-report`, `shipments`, `config`, `deposits`):
  TTL-stale → serve + recompute behind; edit (epoch bump) → entry kept, background recompute starts immediately,
  a request that lands mid-rebuild awaits it (never stale after an edit). The recompute drives the real handler
  (`supplySectionHandler`, `req._hzRecompute`) so cached output is identical. Boot warm (staggered) on non-Vercel only.
- **`swrGet` memo** (small SWR helper): `xero/exceptions` 15 min (`?refresh=1` still live + waits),
  `dtc/mismatch?count=1` 10 min, `bi/reallocations` 10 min, `product/unread` 60 s. `invalidateSupplyCaches` and
  `POST /api/supply/actions/state` mark the `sup:` memos stale; `notes-read-supplier` drops `product-unread`.
- `timeline-notifications`: the three source queries run in parallel.

## supply/inject.html

- `window.fetch` wrapper (top of the script) for **GET `/api/…` only**: in-flight coalescing (concurrent callers of
  the same URL share one response) + a 20 s memory for reference payloads (`lookups`, `skus`, `productions`,
  `likely-dates/all`, `portal-line-costs`). Any non-GET `/api` call or `invalidateDerived` (`window.__hzFetchBust`)
  forgets it. Writes untouched.
- `hzLate(fn)`: the Xero, DTC-mismatch and reallocation badge fetches run ~3 s after page start (immediately later in
  the page's life) so they stop competing with the grid on load.

## Prod notes (Diviyaj)

- Nothing to apply beyond pulling the code. On Vercel the boot warm is skipped (as before, `process.env.VERCEL`);
  everything else is request-driven SWR and works per instance.
- If prod runs as a long-lived Node process the shell memo and section warm give the full gain; if serverless, each
  instance memoises after its first request.
