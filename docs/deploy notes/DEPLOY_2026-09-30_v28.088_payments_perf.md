# v28.088 — PAYMENTS performance: Xero page loads instantly + cache the rest (30-Sep-2026)

Perf (Ben: "clicking Xero payments loaded really slowly"). Server + client, **no migration, no env var,
no product-logic change**.

## The big one: Xero payments page

`renderXeroPayments` awaited `Promise.all([push-queue, xero/exceptions])` before drawing **anything**. But
`xero/exceptions` is a **live Xero bill-by-bill reconciliation sweep** — measured **22.9 s cold** (it fetches every
linked PO's bill from Xero in batches, once per 15-min memo window). So opening the tab hung on "Loading…" for ~23 s,
just to show the **Bills** tab, which doesn't even need exceptions.

Now progressive:
- The push queue draws as soon as it lands (**<1 s**); the page is immediately usable.
- Exceptions load in the background. The Exceptions tab shows "⏳ Checking Xero… ~20 s on first load", its count shows
  "(…)", and the header shows "checking Xero…" until the sweep returns, then everything fills in.
- "↻ re-check" and "resolve all links" use the same progressive loader.

Cold open: **~23 s frozen → <1 s usable** (exceptions fill when ready). Warm (within the 15-min memo): instant.

## The rest of the PAYMENTS tabs

The remaining uncached reads joined the section response-cache (param-free, user-independent, epoch-busted on any
payment edit, boot-warmed):
- `payments-by-supplier` — 1.6 s cold / 0.8 s → 0.3 s
- `remittances` — 0.4 s → 2 ms
- `payment-emails` — 0.4 s → 1 ms

(`deposits`, `payments-report`, `cashflow` were already cached from Sprint A.)
