# Deploy note — v28.062–v28.064 (29-Sep-2026)

Ben's build. Richer Flexport data, PO open-actions/messages surfacing, and the first
cut of the **Flexport booking/quote request** feature. **No new migration and no new
env var** beyond the `FLEXPORT_API_TOKEN` already noted in the v28.029–041 deploy note.

## What's in this batch

- **v28.062 Richer Flexport import.** `runFlexportImport` now maps the fuller shipment
  payload into columns that already exist on `planner.flexport_api_shipments`
  (no schema change): `mbl_number` (ocean master bill / air master airway bill),
  `freight_type`, `total_quoted_amount` (accepted quote), `total_freight_cost`,
  `estimated_shipment_cost`, `planned_transit_time`, `actual_transit_time`. Plus a
  **bounded container-numbers pass**: one `/ocean/shipment_containers` call per
  in-transit ocean shipment that is matched to a PO, capped (`container_cap`, default
  80), never fails the import; `opts.containers:false` disables it. Runs on the existing
  4-hour `POST /api/cron/flexport-import`.

- **v28.063 PO open actions + messages, richer shipment detail.**
  - `po-detail` `flexport` query returns the richer fields and also matches on the PO's
    `flexport_reference`.
  - SHIPMENTS tab: new "Flexport tracking" block (MBL/HAWB, containers, planned→actual
    dates, transit, cost).
  - Every PO detail opens with an **"Open actions & messages"** banner: open actions
    grouped by sub-tab (chips + lines that jump to the tab) + latest supplier/internal
    messages with an unread count.

- **v28.064 Flexport booking/quote request (first cut).** Flexport v3 has ONE creation
  endpoint (`POST /bookings`) and no separate quote endpoint — a booking is lodged as a
  **request** (status submitted), Flexport quotes it, and it is **accepted in the
  Flexport app**. Horizon never auto-commits a shipment.
  - New routes: `GET /api/supply/flexport/booking-registry[?refresh=1]`
    (harvests supplier→shipper-entity + market→consignee-entity refs from existing
    bookings, cached in `app_settings.flexport_entity_registry`; lazy first-run harvest
    on first preview), `GET /api/supply/flexport/booking-preview/:po` (read-only; the
    exact request body + missing/assumed flags), and **`POST /api/supply/flexport/booking-submit`**
    (LIVE WRITE — admin + `confirm` gated; rebuilds the body server-side; refuses if
    required fields are missing).
  - UI: "🚢 Request Flexport booking" on the PO SHIPMENTS tab → preview modal → confirm.

## Also in this window (v28.065–069)
- **v28.065–066** PO grid/detail UI: collapsible open-actions banner; Fulfil ⇄ IS badge
  on its own row under the shipment name; smaller STATUS dropdown; **removed the
  decommissioned Cin7 column** + the "ERP drift approved" checkbox.
- **v28.067** Flexport open actions derived on the PO SHIPMENTS tab (delays/overdue
  milestones) + last-update line; booking-modal date polish (dd-mmm-yy + ready badge).
- **v28.068** Booking cargo sizing (best-value FCL/LCL from pallet estimate, selectable).
- **v28.069 + migration 314** `v_po_finance` now reads `flexport_shipments_effective`
  (was the legacy `flexport_shipments`) and `flex_quote` = invoiced freight first, else the
  accepted quote, **split by the PO's pallet share of its Horizon shipment** so multiple
  POs on one Flexport shipment no longer each carry the full freight. Cashflow freight
  (shipment-level) uses the same invoiced-first/quote-fallback.
