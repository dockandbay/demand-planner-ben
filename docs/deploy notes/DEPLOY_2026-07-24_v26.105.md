# DEPLOY — v26.105 (from live baseline v26.101)

Live is **v26.101** (Diviyaj). This package brings it to **v26.105**. **Code-only — no migrations, no new deps,
no env changes.**

## 🚨 CRITICAL — this includes a supplier-portal-down hotfix. Deploy ASAP.
v26.101 shipped the `dtc_shipment_details` (mig 127) + `key_accounts` joins in the portal's main query
(`POS_SQL_PORTAL`) but **not** the column-qualification fix. Those tables share column names with
`v_po_finance` (`po`, `client_requirements`, all 12 `pack_*`), so the bare references are **ambiguous** and the
portal `bootstrap` call 500s — **the supplier portal fails to load on v26.101.** v26.105 qualifies them
(`calc4.*`). If the live portal is currently erroring with *"column reference \"po\" is ambiguous"*, this is the fix.

## Migrations
**One data seed — `144_branch_delivery_notes_apply.sql`** (no schema change; columns already exist from mig 139/140):
1. Sets the approved **branch delivery notes** on the 8 branches (AU Coghlans / AU FBA / CA FBA / EU iFulfillment
   / UK FBA / UK ILG / US FBA / US Geneva).
2. Stamps those notes onto **all OPEN POs** (`branch_delivery_notes`, only where blank — never clobbers an edit
   or a completed/cancelled PO).
3. Stamps them onto **all OPEN shipments** (`delivery_notes`, from the master PO's branch, only where blank).
Idempotent / re-runnable. (Applied in sandbox: 146 open POs + 83 open shipments stamped.)

## Data dependency (no migration, but note)
Auto Forecast reads **`planner.forecasts` where `level='subcategory'`** (units). That table is populated by the
forecast engine run; it already exists on live. If it's empty/stale, the Auto Forecast forward view will be thin
— re-run the forecast engine to refresh it.
