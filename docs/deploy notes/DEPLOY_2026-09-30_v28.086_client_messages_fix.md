# v28.086 — CLIENT: fix broken MESSAGES tab + faster CLIENTS & AGENTS (30-Sep-2026)

Bug fix + small perf (Ben). Server + client, **no migration, no env var**.

## The bug (MESSAGES didn't open)

`cpRenderMessages` read `var S = _cpMsg` but **`_cpMsg` was never declared** (unlike `_cpComm`), so clicking the
CLIENT ▸ MESSAGES sub-tab threw `ReferenceError: _cpMsg is not defined` synchronously inside `selectClientSub` — the
body stayed on "Loading…" and the page never rendered. Reproduced in sandbox; Ben hit it on live.

Fix: declare `var _cpMsg = { client:'', thread:null };` next to `_cpComm`. MESSAGES now renders the thread list +
conversation pane. Verified: 4 threads, reply box, no console error.

## Slow CLIENTS & AGENTS on click

Two causes:
1. **Serial fetches** — `cpRenderClients` / `cpRenderOrders` fetched `/api/client/lookups`, then `/api/client/clients`
   one after the other. Now the clients fetch is fired immediately, in parallel with lookups (`var _cj = cpGet(...)`
   then consumed in the lookups callback). ~1.7 s cold → the max of the two, not the sum.
2. **`/api/client/lookups` cold cost** — its two `fulfil_sales` GROUP BY scans (channels, countries) were ~3 s cold.
   The user-independent part is now memoised for 5 min (`swrGet('client:lookups')`); only the per-user `me` field
   stays live. Measured **3.0 s cold → 2 ms warm**.

## Prod notes (Diviyaj)

Pull only. `client:lookups` is an in-memory 5-min SWR memo (per instance on Vercel); reference data (rep groups,
price lists, key accounts) shows within 5 min of a change. No schema change.
