# v28.084 — Performance Sprint D: client polish (30-Sep-2026)

Follows v28.081 to v28.083. `supply/inject.html` only, **no migration, no env var, no server change**.

## What changed

- **Stale-while-revalidate on section switch** (generic cached sections: shipments, cash flow, deposits, flexport,
  pipeline, upcoming…): the cached copy still paints at once; if it is older than 60 s the section is refetched in
  the background (server cache / 304) and repainted **only** when the payload changed **and** the view is idle: no
  focused field in the section, no unsaved edit in any field (value ≠ defaultValue), no drawer / overlay / command
  palette open, no click or key in the last 2 s. Otherwise the fresh copy just replaces the cache for the next visit.
  `samples` (always live), `actions` (progressive) and `config` (forms) are excluded. Fixes the "stale until reload"
  gap without ever repainting under someone's hands.
- **Left-rail observer scoped**: it still watches the body (module roots are re-created wholesale) but only
  re-renders when a mutation touches a nav container (`#supply-subnav`, `#prod-subtabs`, `#demand-tabs`, … or a
  node added/removed that is/contains one). Grid repaints (hundreds of row mutations) no longer trigger it.
- **Visibility-aware polling**: the inbox / product-unread / client-thread polls skip ticks while the tab is
  hidden and refresh once on return.
- Section → renderer dispatch pulled out as `renderSectionData(key, d)` (was inline in `selectSection`).

## Left as is (measured, not worth the risk)

- `boot()` retries (0 / 600 / 1800 / 4000 ms): idempotent and cheap; they exist to catch the artefact's late DOM.
- Grid row virtualisation: the grid paints ~105 grouped rows (5.4k nodes); no long tasks measured.
- Pooler keep-alive: the server already keeps one pooled connection warm.
