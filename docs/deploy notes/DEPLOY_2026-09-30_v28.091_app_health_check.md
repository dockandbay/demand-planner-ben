# v28.091 — App health check (CONFIG ▸ Admin ▸ App health) (30-Sep-2026)

New admin tool (Ben). Server + client, **no migration, no env var**. Admin-only, read-only.

## What

A one-click endpoint sweep at **CONFIG ▸ Admin ▸ App health** that times every menu-loaded GET endpoint against the
running server — admin/ops **and** the supplier + client portals — ranks the slow ones and any errors, and gives a
plain-text report to paste into Claude Code for fixing.

## How

`GET /api/config/health-check?live=0|1` (admin-gated):
- Enumerates every param-free GET `/api/*` route from the Express 5 router stack (auto-covers every menu load;
  excludes `:id` detail routes, downloads, crons, callbacks).
- Self-fetches each against `${proto}://${host}` (localhost on the long-lived server, the deployment host on Vercel),
  forwarding the admin's cookie so gated routes authenticate. Small concurrency (5), per-request timeout.
- **Portals**: mints a throwaway 5-minute supplier `portal_sessions` token and a client `client_sessions` cppv_
  token (from the first active portal/client user), self-fetches `/api/portal/*` and `/api/cp/*` with them, and
  deletes both sessions at the end. Never touches a real user's session.
- **Live Xero/Flexport** endpoints are skipped unless `?live=1` (they hit live APIs and are slow).
- Returns per-endpoint `{path, group, ms, status, kb}` ranked slowest-first, counts, and a `report` text block
  (errors first, then slow >1s, then moderate 0.4–1s).

The UI shows KPI tiles (errors / slow / moderate / fast / total), a colour-coded ranked table by area, and a
**"📋 Copy analysis for Claude Code"** button.

## Findings from the first run (sandbox)

167 endpoints. Warm, the remaining slow uncached ones are mostly the **portals** (per-user, so need per-supplier /
per-client caching): `cp/line-sheet` + `cp/stock` (797 KB each), `cp/orders`, `cp/me`, `cp/prices`,
`portal/onboarding`, `portal/price-list/log`, plus param'd analytics (`ssm-backtest`, `scenario/auto-forecast`,
`kpi/in-stock`). Those are the next caching targets. (`/api/health` and `/api/version` reading ~5 s are measurement
contention from the 5-way concurrent sweep, not real.)

## Prod notes (Diviyaj)

Pull only. Admin-only, read-only apart from the two ephemeral 5-min sessions it creates and deletes. On Vercel it
self-fetches the deployment host; each cold sweep reflects worst-case (empty caches).
