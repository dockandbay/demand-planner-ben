## What's in this package

**Supplier portal**
- Actions now ignore productions **≤54** (top PO badge + per-PO MANAGE badge) — only prod ≥55 raises actions;
  new **"⚠ Show all exceptions"** pill on the PO filter (all statuses). Shared `poActionCount()`. (v25.562)
- Auto-update on `portal.html` unchanged from your v25.532 baseline; viewport now `maximum-scale=1` (no zoom). (v25.548)

**Escalation email (v25.548)** — escalate now sends via a shared best-effort `sendResendEmail()` (same method as
the magic link): it **swallows Resend errors and never throws**, so a send hiccup no longer fails the action
("Load failed"). Timeline note + escalated status post regardless; any send issue is logged + returned as a
non-fatal `emailError`. ⚠ Deliverability still depends on the live `RESEND_API_KEY` + a verified `PORTAL_FROM`
domain (you have this set up) — this change only stops the UI failing.

**Shipments / dates**
- Shipment **completion override now flows to the PO** (v25.567): the PO-dates calc joins the shipment on

  3 live POs were in this state), and an explicit `shipments.delivery_date` completion override lands on the PO
  completion **exactly** (skips the +7 warehouse check-in). e.g. PO-55AUWK3 → 27-Aug.
- Completion date is now **overridable on Flexport-linked shipments** (it's arrival+7, not a Flexport field). (v25.565)
- Shipment drawer ▸ POs aboard shows **client name + sales ref** for direct-to-client. (v25.554)

- Shipment drawer: the **Flexport reference is now clickable** through to app.flexport.com. (v25.572)

## Non-blocking note (not in this package)

`planner.flexport_shipments` has **no audit timestamp** (no `updated_at`/`loaded_at`), so the auto-update
data-freshness signal silently skips Flexport and there's no way to read "last synced" from the table. If you
want the nudge to fire on Flexport syncs (and a real last-updated), add `updated_at timestamptz default now()`
and have the n8n Flexport sync stamp it. I can write the migration if you want it.
